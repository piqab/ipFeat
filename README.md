# IP Informer

IP Informer is a macOS app for routing programs, terminal commands and selected domains through sing-box profiles. It runs from the menu bar and provides a Dock icon for opening Settings.

## Build and run

```sh
chmod +x scripts/build-app.sh
./scripts/build-app.sh
open "dist/IP Informer.app"
```

The menu bar icon opens Settings and a compact application panel. Each nonempty group has a colored row of app icons; ungrouped apps have a separate row. Hover to see an app name, click to launch or focus it, or right-click to move or remove it from IP Informer. The `+` icon adds one or more apps to that row. Extra icons scroll with a mouse wheel or trackpad. Removing an app from IP Informer does not delete its `.app` bundle.

The **General** tab controls launch at login and interface language. Routing continues to use IPv4.

## Routing

The **sing-box** tab holds saved server connections and the managed network service status. New connections store their complete client outbound separately; IP Informer generates the working JSON from these connections and its built-in direct, DNS and TUN settings. The former main JSON editor is removed. Existing installations keep their old JSON until **Review generated configuration** shows the changes and unavailable routes have been reassigned individually or to a chosen replacement. Up to 30 configuration snapshots remain available for comparison. The **Profiles** tab holds route profiles. The **Applications** tab groups apps by color and route. All program categories, including groups, ungrouped apps, saved prompt routes, terminal commands and local redirects, start collapsed. One search field at the top filters groups, ungrouped apps, terminal commands and saved prompt routes by name or path. Matching categories expand during search and return to their prior state when the search is cleared. Domain rules have a separate search field. Groups can be renamed and reordered; a new group appears first. Each app's route enable switch sits beside **Launch**. An app in a group follows the group route. Its personal route is shown and used when the app is moved to the ungrouped row. IP Informer adds itself with the `proxy` outbound when available.

The **Default route** controls all other apps. Choose an outbound, **This Mac only**, or **No network**. Localhost remains available in the last two modes. The **Domain routes** section adds global rules such as `*.com → direct` and `*.blabla.eu → proxy`; more specific patterns win, and an explicit app block remains in force. An exact name such as `blabla.eu` is separate from `*.blabla.eu`. Each app can separately allow direct access to local IPv4 networks while its public traffic follows its assigned route. The WebKit profile selector can route the shared WebKit networking process through any saved profile or leave it to ordinary rules. This setting may affect embedded pages from several apps. Generated routing and DNS use IPv4; IPv6 connections are rejected.

The **Terminal commands** section assigns exact executable paths such as `/usr/bin/ssh` to a route and can allow direct local IPv4 access. With the IP Informer sing-box patch, new apps ask for a route for unknown child commands by default. The choice is saved for that app and executable path. A separate, optional **Ask for a route for unlisted processes** switch covers apps, commands and background processes that are not in IP Informer. It asks on the first public IPv4 connection. **Save route** creates a permanent executable-path rule in the Applications tab's **Saved from route prompts** category. **Use once** applies only to the current process launch. The shared program search covers these saved routes and commands; items are sorted by name and can be selected individually or together for moving or deleting. Private and localhost traffic is not delayed. The prompt stays open until you choose. If the first connection waits 20 seconds without an answer, it is blocked; a later choice applies to subsequent connections. Both prompt features require the patched local engine. See [NETWORK_ROUTING_SETUP.md](NETWORK_ROUTING_SETUP.md) and [SING_BOX_PATCH.md](SING_BOX_PATCH.md).

The local sing-box patch is pinned to `1.14.4-6`. It reloads app, command and domain policy without restarting the TUN, attributes child traffic through verified parent processes, and provides the route prompts. A matching global domain rule takes precedence over a process prompt. Prompt choices can be saved as permanent process routes or applied once for the current launch. Saved process routes appear in Programs, can be searched and moved into groups, and are included in encrypted backups. Installing the patch needs macOS administrator authorization. While it is active, automatic engine updates are disabled; the app can restore the saved official engine. The VPS always uses official sing-box.

The sing-box tab distinguishes the IP Informer network LaunchDaemon, its updater service, and separately launched sing-box processes. It shows the managed process, configuration path and TUN state. Install, reinstall, restart, remove and network-log actions are available there. Installing or removing services requires macOS administrator authorization; removal keeps saved connections and engine binaries. A separate sing-box process is reported but is not controlled by IP Informer profiles.

The **AI** tab stores multiple model profiles: OpenAI-compatible endpoints, local Ollama, Anthropic and Gemini. DeepSeek presets fill the matching endpoint and current model name. Each profile chooses the request and answer language: macOS language, Russian, English or a custom answer language. **Test model** uses the fields currently shown; **Save model** makes them available to the `?` button in a route prompt. The button sends only the shown executable and immediate parent paths and registered app name, and asks for an explanation; AI never chooses a route. API keys are stored in Keychain and included only in the password-encrypted configuration export. The route window remains open while a model works. Remote endpoints require HTTPS; local loopback endpoints may use HTTP.

## Client and server configurations

The **New server** wizard generates matching client and server JSON for a new Linux VPS, validates both with sing-box, and can install the server over SSH. The VPS fetches the exact official release metadata and Linux archive over IPv4, verifies the archive against GitHub's SHA-256 digest, and enables the systemd service at boot. After automatic deployment, IP Informer opens a separate SSH session and checks the exact config hash, sing-box version, installed files, and active and enabled systemd service. It adds the client only when all checks pass. If SSH closes or a check fails, the installation stays pending and its log remains available. The wizard can copy either a self-contained VPS installer or a self-contained installer for another Mac/Linux host with SSH access. The host script downloads and verifies the Linux archive, transfers it to the VPS and installs the service. After the script prints an `IPINFORMER_INSTALL_OK` line, paste it into the pending installation to add the client with **Installation not verified** status. The line matches the expected version and server JSON hash; it is not an independent remote status check. Each saved server has **Installation / Check…** to copy either script again, check the VPS over SSH, and inspect systemd status and recent journal entries. Installation scripts contain credentials and should be kept private. Automatic pairs are available for VLESS + Reality, Shadowsocks 2022, VMess, Trojan, Hysteria2 and AnyTLS. TLS technologies can use ACME or embedded PEM certificate and key. Several client connections can be stored and selected as profiles. Each connection has **Client JSON**, **Server JSON**, and **Share QRS** actions. The client JSON and QRS include enabled global domain routes and their required outbounds; a standard sing-box client applies them locally. The QRS display transfers a standalone IPv4 client profile to the official sing-box Android app (version 1.13 or newer); it contains client credentials, potentially for multiple servers. Reimport QRS after changing domain rules. Server secrets are stored in Keychain. See [NETWORK_ROUTING_SETUP.md](NETWORK_ROUTING_SETUP.md).

Settings can be exported to a password-encrypted archive and restored on another Mac. Version 3 contains JSON and its history, profiles, groups, app, command and domain rules, permanent routes saved from prompts, client and server JSON, pending VPS installations, redirects, AI profiles and readable API keys, the interface language, and launch-at-login preference. It omits retired IP sources, check intervals and widget settings. Version 1 and 2 archives remain readable; those retired fields are ignored when restored. Export stops if a saved server JSON is missing from Keychain or a Keychain read fails. If restoring a record fails, IP Informer restores the prior Keychain entries and pending VPS installations and reports any rollback errors. Restored server connections require a fresh VPS verification. The archive does not contain installed `.app` bundles, sing-box binaries or the system service. Missing apps, commands and saved process routes are disabled during restore; saved process routes can be relinked to an executable in the Applications tab. The application icon appears in both the Dock and menu bar; clicking it in the Dock opens Settings.

The General tab offers a system-language option and manual Russian, English, and Simplified Chinese choices. Restart IP Informer after changing the language to apply it across all windows and menus. The language choice is included in encrypted backups.
